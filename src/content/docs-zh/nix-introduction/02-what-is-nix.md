要回答「Nix 是什么？」这个问题非常不容易。

我们先来看看官方的说明。

https://github.com/NixOS/nix

> Nix, the purely functional package manager

这里说 Nix 是纯函数式包管理器。想理解这句话的含义，首先必须弄清楚包管理器究竟是一类什么样的软件。

由于它已经成为现代开发中理所当然的工具，我们很容易忘记：包管理器其实是相当复杂的软件。在学习 Nix 之前，先来梳理一下前置知识。

## 什么是包管理器？

这里引用 Debian 的定义。

> _A package manager keeps track of what software is installed on your computer, and allows you to easily install new software, upgrade software to newer versions, or remove software that you previously installed._\
> [什么是包管理器？](https://www.debian.org/doc/manuals/aptitude/pr01s02.en.html)

这段话说的是：包管理器是一种管理计算机上已安装软件，并让你能够轻松添加／更新／删除软件的工具。

刚才不知不觉地出现了「安装」一词，那么「安装」到底是什么呢？
我们来想想它和下载的区别。下载是把互联网上的资源取到本地计算机上。而安装则是把下载下来的资源放到本地计算机的恰当位置、完成必要的配置，让这份资源可以被使用。

## 什么是软件包？

包管理器以「软件包」为单位管理软件。软件包的内容通常包含以下这些东西：

- 可执行文件
- 共享库
- 静态资源（文本、音频、字体，等等……）

通过包管理器安装软件时，包管理器会自动把软件包中包含的文件放到恰当的位置。例如在一般的 UNIX 系系统上，可执行文件会被放到 `/usr/bin`，共享库放到 `/usr/lib`，静态资源放到 `/usr/share` 等位置。这样一来，可执行文件就能通过 PATH 环境变量在 shell 中作为命令执行，共享库也能被动态链接器加载。

相对地，编程语言的包管理器往往会把软件包统一集中到专用目录中管理。

## 包管理器的定义

现代的包管理器与过去的相比功能丰富得多。例如 Node.js 的 npm 不仅管理 npm 包，还能通过 lock 文件固定依赖关系、执行脚本。Rust 的 Cargo 不仅能固定依赖关系，还能构建项目、运行测试、生成文档。而 Python 的 pip 与 npm、Cargo 相比功能就没那么多了。可见，同样叫「包管理器」，功能上却可能相差甚远。

因此，为了让后续的讨论更顺畅，这里先定义一下本书所说的「包管理器」。

1. 从软件包仓库下载软件包
2. 自动解析软件包的依赖关系
3. 拥有构建系统
4. 自动完成软件包的安装

具备以上功能的，我们称之为「包管理器」。

整套流程是：从软件包仓库自动获取目标软件包及其依赖，按照软件包定义完成构建，然后把软件本体和配置文件自动放置到用户的环境中。

关于构建系统，也有像 Debian 的 apt 那样不在本地构建、而是直接安装已构建产物的包管理器，不过这里我们暂不考虑这种情况。

## Nix 有什么不同？

Nix 拥有在其他包管理器中见不到的、极为独特的机制。本书尤其会讲解以下功能：

1. 纯函数式构建系统
2. 借助 Nix Store（仓库）对软件包与依赖关系进行严格管理
3. 借助 Nix 语言与 Flakes 实现声明式构建
4. 借助 Profiles 实现非破坏性的软件包配置管理

一下子冒出了这么多专有名词，不过后文会逐一讲解，请放心。
